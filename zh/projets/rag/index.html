个人项目 / 文档 RAG

作品集文档 RAG

这个助手曾根据我的文档回答关于作品集的问题，使用 VPS 上的 ChromaDB 检索内容，并通过外部 API 调用模型。

当前状态
已记录的原型 / 界面已移除
技术
Astro / Node.js / ChromaDB / API LLM

背景

我曾将这个助手集成到旧版作品集中，让访客可以直接询问我的项目和 Markdown 笔记内容，无需逐页浏览。

用 Ollama 做过本地测试后，我把检索留在 VPS 上，将生成交给外部 API。

测试中的观察

试过的 4B 和 8B 模型都没有给出预期的回答，8B 在当时的配置下也太慢。

运行方式与架构

系统分为两个阶段：先准备文档，再针对每个问题检索相关段落。

索引

Markdown 文件被切分为段落，转换为 embeddings 后存入 ChromaDB 建立索引。这一步在处理查询之前完成。

ChromaDB 通过 Docker 运行在 Linux VPS 上。

查询

Node.js 接收问题，从 ChromaDB 检索相关段落，将上下文组装进 prompt，再通过外部 API 调用模型。生成的回答随后在 Astro 界面中逐步显示。

局限

这个原型目前没有可供参考的质量、延迟或覆盖率量化数据。

可进一步评估的方向

  • 语料的时效性与可追溯性；
  • 使用代表性问题评估检索效果；
  • 非公开文档的访问权限管理；
  • 来源展示与不确定性的明确处理。
