Personal project / Document RAG

Document RAG for my portfolio

A retrieval-augmented system built to query the documented projects and knowledge in an earlier version of my portfolio, then progressively display an answer grounded in retrieved passages.

Current state
Documented prototype / interface removed
Technologies
Astro / Node.js / ChromaDB / Ollama

Context

This project belonged to an earlier version of my portfolio. It let visitors ask about my projects or knowledge recorded in Markdown files without opening every page.

The assistant was previously deployed but has been removed from the current site. This page preserves the documented architecture and decisions; it does not bring back a chatbot or interactive service.

How it worked and its architecture

The system is easier to understand when corpus preparation is separated from the query shown in the diagram.

Indexing

Markdown files about projects and knowledge formed the corpus. Their content was prepared for retrieval and stored in ChromaDB.

ChromaDB ran in Docker on a Linux VPS. The diagram does not show this phase, which happened before a question could be processed.

Query

The Node.js backend received the question, searched ChromaDB for relevant passages and assembled the context sent to the generative model served by Ollama in the documented versions of the project.

The answer then returned to the Astro interface and appeared progressively. No specific transport protocol or retrieval setting is inferred from the diagram.

Documented components

Astro
Portfolio interface and progressive answer display.
Markdown
Files describing projects and knowledge in the corpus.
Node.js
Backend receiving the question and coordinating retrieval and generation.
ChromaDB
Document retrieval database running with Docker on a Linux VPS.
Ollama
Generation service used by the documented versions of the project.

Current state

The interface in the diagram is no longer deployed on this portfolio. This page exposes no active demo, API or VPS access.

The project is presented as a technical case study: the visual explains a past architecture, not current availability.

Limits and scope

What this documentation does not demonstrate

  • The diagram covers a query, not corpus preparation, updates or re-indexing.
  • The ‘Top-K’ label represents a ranked selection of passages; no value for K is documented here.
  • No quantitative quality, latency or coverage measurement is presented on this page.

Questions for a future version

The following are general design considerations, not features claimed for the prototype:

  • corpus freshness and traceability;
  • retrieval evaluation with representative questions;
  • access control for non-public documents;
  • source presentation and explicit handling of uncertainty.
